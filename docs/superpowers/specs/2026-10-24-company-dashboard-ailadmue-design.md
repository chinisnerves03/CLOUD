# Company Dashboard — เฟส 1: AI ลัดมือ

วันที่: 2026-10-24 · สถานะ: ร่างรอเจ้าของตรวจ

## 1. เป้าหมาย
หน้า Dashboard บริษัทที่เจ้าของ **สั่งงานเอเจนต์ได้จาก iPhone** เฟส 1 ครอบคลุมเฉพาะแผนก **AI ลัดมือ** (ทำคลิป + สำรวจช่องอื่นว่าเนื้อหาแนวไหนยอดวิวสูง) แผนก **UDC** (มอด BeamNG) เป็นเฟส 2 ใช้โครงเดียวกัน

เกณฑ์สำเร็จ
- เปิดหน้าบนแอป Claude บน iPhone ได้ และเห็นสถานะงาน/คลิป/ผลสำรวจ
- กด "สั่งงาน" เลือกเอเจนต์ พิมพ์คำสั่ง แล้วมีเซสชัน Claude Code เริ่มทำงานบน repo `chinisnerves03/CLOUD`
- ผลงานและโค้ดทั้งหมดถูกเก็บใน GitHub; สถานะ/คิว/ผลสำรวจเก็บในฐานข้อมูลของหน้า

## 2. ข้อจำกัดที่รู้แล้ว
- เจ้าของเปิด GitHub/GitHub Pages บน iPhone ไม่ได้ จึงใช้ Artifact บน claude.ai เป็นหน้าหลัก
- เอเจนต์ไม่ทำงานเองตลอดเวลา เริ่มเมื่อมีการสั่ง (หรือตั้งเวลาภายหลัง)
- vidIQ ใช้เครดิต (10 ต่อการวิเคราะห์คลิป, 5 ต่อการค้นหา outlier) ElevenLabs ใช้เครดิตต่อเสียง
- ยังไม่มีการยืนยันว่าหน้าที่เผยแพร่แล้วเรียกตัวเชื่อมต่อ (vidIQ, Claude Code Remote) ได้ครบตามที่ต้องการ ต้องทดสอบจริงก่อนส่งมอบ (ข้อ 9)

## 3. หน้าจอ (5 แท็บ)
1. **ภาพรวม** — จำนวนงานค้าง/กำลังทำ/เสร็จ, คลิปล่าสุด, เครดิตที่รู้ (กรอกเอง), ปุ่มลัดสั่งงาน
2. **คลิป** — รายการคลิป (เลข, สไตล์, หัวข้อ, ความยาว, สถานะโพสต์: ยังไม่โพสต์/IG/YouTube, ผลลัพธ์ที่กรอกเอง เช่น ยอดดู/skip rate), ลิงก์ไฟล์ใน GitHub
3. **สำรวจ** — ผลสำรวจช่องอื่น: ไอเดีย, hook, ยอดดู, แนวที่ซ้ำ ปุ่ม "สำรวจเพิ่ม" (vidIQ, ยืนยันค่าเครดิตก่อน) และ "ขอให้ Claude สรุปแนวที่ควรทำ"
4. **สั่งงาน** — เลือกเอเจนต์ → พิมพ์คำสั่ง → ส่ง
5. **บันทึก** — ประวัติงานและผลลัพธ์พร้อมลิงก์

ดีไซน์: แนวตั้ง ใช้มือเดียวบนมือถือ ตัวอักษรไทย (Prompt) โหมดสว่าง/มืดตามระบบ

## 4. เอเจนต์ (4 ตัว) — บทบาท = คำสั่งตั้งต้นในไฟล์ `company-dashboard/agents/*.md`
| เอเจนต์ | หน้าที่ | เครื่องมือ |
|---|---|---|
| ตัวสำรวจช่อง | หาคลิปไทยที่ยอดโดดเด่น วิเคราะห์ hook/รูปแบบ สรุปเป็นไอเดียที่เหมาะกับเพจ | vidIQ |
| ตัวทำคลิป | สร้างคลิปจากไอเดียที่อนุมัติ (สคริปต์ → เสียง → เรนเดอร์ด้วย HyperFrames) ใช้ `ai-ladmue/clips/hfkit.py` | ElevenLabs, HyperFrames |
| ตัวเขียนแพ็กเกจโพสต์ | แคปชั่น IG, ชื่อ/คำอธิบาย/แท็ก YouTube Shorts, ข้อความ CTA | – |
| ตัววิเคราะห์ผล | อ่านตัวเลขที่เจ้าของกรอก (ยอดดู, ดูจนจบ, skip) แล้วบอกว่าควรแก้ฮุก/หัวข้อ/รอ | – |

กติกาทุกตัว: ไม่เดาตัวเลข, ระบุข้อจำกัดเสมอ ("ผมรับประกันยอดวิวไม่ได้"), ถามยืนยันก่อนใช้เครดิต, ไม่ส่ง/โพสต์ออกภายนอกเอง

## 5. การสั่งงาน (ลำดับ)
1. เจ้าของเลือกเอเจนต์และพิมพ์คำสั่งบนหน้า
2. หน้าเขียนเอกสารงานลงฐานข้อมูล `tasks/{id}` สถานะ `queued`
3. ถ้าเป็นงานที่ใช้เครดิต แสดงกล่องยืนยัน (ค่าโดยประมาณ) ก่อนไปขั้นต่อไป
4. หน้าเรียกตัวเชื่อมต่อ **Claude Code Remote** เพื่อเปิดเซสชันใหม่บน repo พร้อมคำสั่งของบทบาท + คำสั่งเจ้าของ (สถานะ `running`, เก็บ session id)
5. เอเจนต์ทำงาน, commit/push ขึ้น branch, สรุปผลลง `log` (ผ่านเซสชัน Claude ที่เขียนฐานข้อมูลได้)
6. หน้าเห็นสถานะอัปเดตทันทีผ่านการสมัครรับข้อมูล (`onSnapshot`)

ถ้าข้อ 4 เรียกจากหน้าเว็บไม่ได้ (ดูข้อ 9) ทางสำรอง: หน้าเก็บคำสั่งไว้ในคิว แล้วเจ้าของสั่งให้ผมในแชท "ทำคิว" ผมอ่านคิวจากฐานข้อมูลแล้วลงมือทำ

## 6. ข้อมูล (db)
- `tasks/{id}`: agent, prompt, status (`queued|running|done|failed`), createdAt, sessionId?, creditEstimate?, resultSummary?, links[]
- `clips/{n}`: number, style, topic, durationSec, file, platforms{ig,yt}, metrics{views?,completionPct?,skipPct?,notes?}
- `ideas/{id}`: title, source (ลิงก์/แนวที่เห็น), hookStyle, effort, status (`new|approved|made|dropped`)
- `research/{id}`: platform, url, views, hook, format, whyItWorks, collectedAt
- `log/{id}`: ts, agent, text, links[]
- กฎ: เจ้าของ/ผู้แก้ไขเท่านั้นที่เขียนได้ (ไม่มีข้อมูลลับ ไม่เก็บคีย์/รหัสผ่าน)
- เมล็ดข้อมูลเริ่มต้น: ผมใส่ข้อมูลคลิป 14–27 จาก repo (ผ่านเครื่องมือ ไม่ฝังในโค้ดหน้า) และปล่อยตัวเลขผลลัพธ์ว่างจนกว่าเจ้าของกรอก

## 7. ความสามารถของ Artifact ที่จะประกาศ
`db`, `user` (ตรวจสิทธิ์เจ้าของ), `mcp` (vidIQ, Claude Code Remote), `sample` (ให้ Claude สรุป/คิดไอเดียในหน้า) ไม่ประกาศ `artifact`/`room`/`assets` ในเฟส 1

## 8. ไฟล์ใน repo
```
company-dashboard/
  README.md              # วิธีเปิดหน้า/สั่งงาน/ข้อจำกัด
  dashboard.html         # ซอร์สของหน้า (เผยแพร่เป็น Artifact)
  agents/                # คำสั่งตั้งต้นของแต่ละเอเจนต์ (.md)
  seed/clips.json        # ข้อมูลคลิปตั้งต้น
```

## 9. ความเสี่ยงและข้อที่ต้องทดสอบก่อนส่งมอบ
1. หน้าเรียก `Claude Code Remote` (`create_session`) และ vidIQ ได้จริงบน iPhone ไหม ต้องดูสคีมาของเครื่องมือและทดสอบ 1 ครั้งที่ไม่เสียเครดิต
2. สิทธิ์ที่ผู้ชมต้องกดอนุญาตครั้งแรก (consent) ใช้งานได้บนมือถือหรือไม่
3. ฐานข้อมูล: ตรวจว่าผู้ชมระดับต่ำเขียนข้อมูลไม่ได้ (ทดสอบด้วยระดับสิทธิ์ต่ำกว่า)
4. ค่าใช้จ่าย: กล่องยืนยันต้องแสดงก่อนทุกงานที่ใช้เครดิต
5. การเรนเดอร์คลิปในเซสชันใหม่ต้องมีเครื่องมือ (Node, FFmpeg, HyperFrames) ตั้งค่าในสภาพแวดล้อมเซสชัน ไม่แน่ใจว่าเซสชันใหม่มีครบ อาจต้องมีสคริปต์ติดตั้งในคำสั่งตั้งต้น
